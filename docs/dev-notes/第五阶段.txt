# FundPilot AI — Phase 5 开发指令：专业 Dashboard

现在开始开发 FundPilot AI Phase 5。

Phase 1～4 已完成，当前 pytest 全部通过。

Phase 5 的目标不是增加新的复杂后端能力，而是：

> 将现有基金数据、持仓、收益、历史表现、最大回撤等能力整合成一个真正可用的 Dashboard。

要求：

**稳定 > 炫技**
**数据准确 > 动画效果**
**信息层次 > 堆功能**

# 五、颜色语义

统一基金数据颜色。

建议：

```text
收益 / 上涨：
红色

亏损 / 下跌：
绿色

普通数据：
深灰 / 黑色

辅助信息：
灰色
```

这是中国基金/股票用户比较熟悉的视觉语义。

必须统一。

例如：

```text
+396.00
+11.00%
```

显示红色。

```text
-200.00
-5.25%
```

显示绿色。

不要出现一个地方红涨绿跌、另一个地方绿涨红跌。


或者现有持仓 API。



# 十一、基金名称

基金名称必须使用后端返回的数据。

```javascript

```

# 十二、添加持仓

保留现有添加持仓能力。

但是重新设计 UI。

点击：

```text
+ 添加持仓
```

弹出 Modal。

表单：

```text
基金代码
持有份额
成本价格
```

按钮：

```text
取消
添加
```

提交后：

1. 调用现有 POST API
2. 成功
3. 关闭 Modal
4. 刷新 Dashboard
5. 显示成功提示

失败：

```text
基金不存在
数据源暂时不可用
持仓已经存在
```

等。

不要直接显示 Python 异常堆栈。

---

# 十三、编辑持仓

点击：

```text
编辑
```

打开 Modal。

允许修改：

```text
份额
成本价格
```

基金代码不要允许随便修改。

如果要换基金：

```text
删除原持仓
+
重新添加
```

这样数据库设计更简单，也避免基金代码唯一约束产生复杂逻辑。

# 二十、错误处理

统一前端错误提示。

例如：

```text
基金数据暂时无法获取
```

而不是：

```text
503 Service Unavailable
```

开发调试信息可以在 console 中保留。

用户界面不要暴露 Python traceback。

---

# 二十一、数据更新时间

因为目前没有实时估值。

必须明确：

```text
当前净值：最新已确认净值
```

而不是：

```text
当前价格
实时价格
实时净值
```

可以显示：

```text
净值日期：2026-09-21
```

这个信息应该来自后端真实数据。

---

# 二十二、后端是否需要新增 API

原则：

> 能复用现有 API，就不要新增 API。

优先复用：

```text
GET /api/portfolio/summary
GET /api/portfolio/holdings
GET /api/funds/{code}
GET /api/funds/{code}/performance
GET /api/portfolio/holdings/{id}/history
```

只有当 Dashboard 确实缺少必要数据时，才增加 API。

如果需要增加：

例如：

```http
GET /api/portfolio/dashboard
```

必须先确认现有 API 无法合理满足需求。

不要为了 Dashboard 随便增加重复接口。

# 三十一、最终产品原则

Phase 5 的最终目标不是“功能越多越好”。

而是让：

```text
FundPilot AI
```

看起来已经像一个真正的个人基金数据终端。

用户打开网页后：

```text
先看到自己的钱
↓
再看到自己的收益
↓
再看到自己的持仓
↓
再看到历史表现
↓
最后才深入查看基金
```

信息层级必须符合这个顺序。

开始开发 Phase 5。
